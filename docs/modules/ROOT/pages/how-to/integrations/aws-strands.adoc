== Choose retrieval and sharing behavior

anchor:_configuration[]

Pick a surface before configuring either class: use `Neo4jSessionManager` to transparently persist and restore the whole conversation transcript, and add `Neo4jMemoryStore` only when the agent also needs to pull retrieved memory into its own reasoning loop through `MemoryManager`. `context_graph_tools(...)` is a third, pull-based option: the model decides when to call the tools. The subsections below cover each surface, how to combine them, how to share memory across agents and their limits.

=== Session manager options

anchor:_constructor_reference[]

`Neo4jSessionManager` persists and restores transcripts; it does not require the model to invoke a memory tool. One Strands session maps to one `Conversation`. Its constructor requires exactly one of `settings=` or `memory_client=`. Prefer settings-owned lifecycle for a synchronous Strands application.

[cols="1,1,3",options="header"]
|===
|Argument |Default |Effect

|`session_id` |required |Strands session identifier; maps to one `Conversation`.
|`settings` / `memory_client` |`None` |Exactly one. With `settings`, the manager constructs and closes its own client. A `memory_client` must not already be connected on another event loop.
|`user_id` |`None` |Scopes writes, and the preference lookup used for injection, to one user.
|`retrieval_config` |`None` |A `Neo4jRetrievalConfig` turns on per-turn context injection. `None` means persistence only.
|`extract_entities` |`True` |Runs entity extraction on stored messages (Bolt only; NAMS extracts server-side). Each message is written first and extracted in a separate step. A failed extraction is logged as a warning, and the message stays stored.
|`defer_extraction` |`False` |Starts each message's entity extraction in the background, so the agent call returns once its messages are written. One session's extractions run one at a time, in write order. Each is bounded by `request_timeout`, and a failure is logged as a warning. A late redaction that deletes a message before its extraction starts skips that extraction. If that delete fails, the message stays stored and is never extracted. The backlog of extractions has no cap. Extractions slower than the message rate let it grow for as long as the manager lives. The option does nothing on NAMS, which extracts on the server.
|`record_tool_calls` |`False` |Records observed tool-use blocks in reasoning memory for audit.
|`request_timeout` |`30.0` |Seconds to wait for each backend call. Writing a message takes up to three calls: the write, its entity extraction, and its tool-call record. A write that times out is a failed write, handled by `on_persist_error`. It keeps running, and the retry takes its result instead of writing again, so the message is stored once. A hook waits as long as its batch of writes can take. If that wait runs out, the writes go on in the background, and a warning is logged.
|`restore_limit` |`None` |Maximum messages restored into the agent. `None` uses the backend default; Bolt returns up to 1000.
|`on_persist_error` |`"raise"` |What a failed memory write does. `"raise"` raises `SessionException` to the agent call. `"warn"` logs a warning, and the agent call goes on. In both modes the message stays queued. The next agent call retries it before it starts, ahead of any later message. A message is dropped if that retry fails too. At close, a message whose write already failed is dropped if it fails again. A dropped message gets an ERROR log that names its session, role, and position. So after a failed flush, only messages from the current turn stay queued. A failure at close leaves messages unwritten for good, so in both modes it is logged as an ERROR with their number. With `"raise"`, each agent call raises while the backend stays down. That stops when the backend recovers or the manager closes. Failures to restore history always raise.
|`bridge` |`None` |The background loop to run memory I/O on. It needs `memory_client=`, already connected on that loop. A manager given a bridge closes neither the bridge nor the client. `SharedMemory` passes it for you.
|`background_hook` |`None` |Called with a short name, such as `"extract:<session_id>"`, when a deferred extraction or a tool-call recording starts. It returns a function that runs once when that task ends, whether it succeeded, failed, or was cancelled. A task that ignores the cancel when the background loop stops still gets its done call, with a warning. Both run on the background thread, so they must be thread-safe and fast. An error from either is logged as a warning and never fails a write. `SharedMemory` passes its own.
|===

`Neo4jSessionManager.for_nams(session_id, **kwargs)` builds a manager for the hosted service from `MEMORY_API_KEY` and optional `MEMORY_ENDPOINT`; `Neo4jMemoryStore.for_nams(config)` does the same for a store. The Bolt program above uses settings instead.

=== Use the session manager from async code

The manager's hooks run on the agent's event loop and await memory I/O on the manager's own background loop. A slow write does not stall other tasks on the agent's loop. This matters when one server loop runs many sessions.

Strands calls `initialize` synchronously while it builds the `Agent`, so by default the history load blocks. In async code, await `aopen()` before you build the agent. The manager then restores the preloaded history with no I/O. Close with `await manager.aclose()` instead of `close()`, so the final write and the client close are awaited too.

A close runs every step even after one fails. It writes the queue, waits for tool-call mirroring still running, waits for deferred extractions, closes an owned client, then stops the background loop. Each wait is bounded like the wait for the queue. Work still running after it is cancelled, and a warning says how many tasks. The cancelled tasks get up to 5 seconds to unwind before the client closes. Only a manager that owns its background loop waits for deferred extractions. A manager from `SharedMemory` leaves them running, and `SharedMemory` waits for them when it closes. It raises the first error. An error from a later step is logged as an ERROR instead. An interrupt is the exception. A `KeyboardInterrupt`, `SystemExit`, or `asyncio.CancelledError` from a later step is raised, and the earlier error is logged.

[source,python]
----
manager = Neo4jSessionManager(session_id, settings=settings)
await manager.aopen()
try:
    agent = Agent(model=model, session_manager=manager)
    result = await agent.invoke_async(prompt)
finally:
    await manager.aclose()
----

=== Serve many sessions from one client

A manager built from `settings=` owns a client and a background thread. A server that runs many sessions at once would then hold one connection pool and one thread per session. Build one `SharedMemory` at startup instead, and ask it for a manager per session. Every manager it builds runs on one client and one background thread.

[source,python]
----
from neo4j_agent_memory.integrations.strands import SharedMemory

shared = SharedMemory.open(settings)  # connects once, blocking


async def handle(session_id: str, user_id: str, prompt: str) -> str:
    manager = shared.session_manager(session_id, user_id=user_id)
    await manager.aopen()
    try:
        agent = Agent(model=model, session_manager=manager)
        return str(await agent.invoke_async(prompt))
    finally:
        await manager.aclose()


# at shutdown, after every session has closed
await shared.aclose()
----

`session_manager()` passes its keyword arguments to `Neo4jSessionManager`. Its `request_timeout` defaults to the one given to `open()`. A manager's `close()` or `aclose()` writes its own messages and returns. It leaves the client connected and the loop running for the other sessions. `SharedMemory.aclose()` or `close()` first waits for the tasks still running on the loop, such as deferred extractions. Its `timeout` argument bounds that wait. It defaults to 30 seconds and must be a positive finite number. The tasks still running after it are cancelled, and a warning gives their number. They get up to 5 seconds to unwind. Then the client closes and the loop stops. A second call does nothing. Close every manager first, because closing the loop cancels a write still running.

A host that stops idle sessions needs to know about work that outlives the agent call. Deferred extraction is one example. Pass `background_hook` to `open()`, and every manager reports its background tasks to it. On Amazon Bedrock AgentCore Runtime, `BedrockAgentCoreApp` tracks them, so the session reports busy until they end:

[source,python]
----
def track(name: str):
    task_id = app.add_async_task(name)
    return lambda: app.complete_async_task(task_id)


shared = SharedMemory.open(settings, background_hook=track)
manager = shared.session_manager(session_id, defer_extraction=True)
----

The hook and the function it returns run on the background thread. Keep them thread-safe and fast. A manager built by `SharedMemory` takes its hook, so passing `background_hook` to `session_manager()` raises `TypeError`.

=== Inject retrieved context per turn

anchor:_retrieval_injection[]

Pass `retrieval_config=` to have the session manager search long-term memory on every user message and prepend the matches to that message inside a `<user_context>` block. The stored message stays the user's original text, and nothing is prepended when no result passes `min_score`. Each turn costs one to three extra backend searches, which is why injection is off by default.

This partial snippet reuses `session_id` and `settings` from `strands_memory_tutorial.py` and shows only the manager construction.

[source,python]
----
from neo4j_agent_memory.integrations.strands import (
    Neo4jRetrievalConfig,
    Neo4jSessionManager,
)

manager = Neo4jSessionManager(
    session_id,
    settings=settings,
    retrieval_config=Neo4jRetrievalConfig(
        top_k=10,                    # results per memory kind
        min_score=0.2,               # similarity floor (Bolt only)
        include_entities=True,
        include_preferences=True,
        include_facts=False,
        context_tag="user_context",  # wrapper tag
    ),
)
----

On NAMS only entity search runs: preferences and facts are skipped, and `min_score` is not applied.

=== Memory store options

anchor:_memory_store[]
anchor:_store_limitations[]

`Neo4jMemoryStore(Neo4jMemoryStoreConfig(...))` implements Strands' memory-store surface. Configure it on `MemoryManager(stores=[store])` for agent-loop retrieval. `Neo4jMemoryStoreConfig` takes:

* `name` (required) identifies the store, and `description` describes it to the model.
* Exactly one of `client` (borrowed and left open) or `settings` (the store constructs and closes its client).
* `max_search_results`, `min_score` (default `0.2`) and the `include_entities`, `include_preferences` and `include_facts` switches (all `True`) control retrieval.
* `writable` (default `True`) and `extraction` (default `False`) control writes. Store extraction is off by default, so a store with the defaults does not capture every turn.
* `conversation_id` selects the sink conversation for writes, and `user_id` scopes them.
* `graph_tools` (default `True`) adds the store's graph tools to the agent.

Reuse one configuration for several stores with `dataclasses.replace(config, name="team")`. See https://github.com/neo4j-labs/agent-memory/tree/main/examples/strands-memory-store[the maintained memory-store example] for its lifecycle and verified settings.

=== Combine the store and the session manager

anchor:_pairing_with_the_session_manager[]

Choose one writer when combining a store and session manager. Leave store extraction disabled when the session manager owns transcript writes; otherwise a turn is written and extracted twice, and the session manager raises `ValueError` when it detects that pairing. Inject retrieved memory from one side only: either omit `retrieval_config` on the session manager, or pass `injection=False` to `MemoryManager`. The session manager logs a warning when both inject. Strands invocation-triggered extraction and backend entity extraction are separate stages; a successful write does not prove every derived entity is ready.

See https://github.com/neo4j-labs/agent-memory/tree/main/examples/strands-session-manager[the maintained session-manager example] for two agents with separate sessions over one graph.

`context_graph_tools(...)` returns four Strands tools for a Bolt database. Tool names describe available actions; the model can choose not to call them.

[source,python]
----
import os

from strands import Agent

from neo4j_agent_memory.integrations.strands import context_graph_tools

tools = context_graph_tools(
    neo4j_uri=os.environ["NEO4J_URI"],
    neo4j_user=os.environ["NEO4J_USERNAME"],
    neo4j_password=os.environ["NEO4J_PASSWORD"],
    neo4j_database=os.getenv("NEO4J_DATABASE", "neo4j"),
    embedding_provider="bedrock",                  # or "openai", "vertex_ai"
    embedding_model="amazon.titan-embed-text-v2:0",
    aws_region=os.environ["AWS_REGION"],
)
agent = Agent(model=os.environ["BEDROCK_MODEL_ID"], tools=tools)
----

`neo4j_uri` and `neo4j_password` fall back to `NEO4J_URI` and `NEO4J_PASSWORD`. `StrandsConfig.from_env()` reads the whole configuration from the environment and is passed as `context_graph_tools(**config.to_dict())`. It reads `NEO4J_USER`, not `NEO4J_USERNAME`, and also `NEO4J_DATABASE`, `EMBEDDING_PROVIDER`, `EMBEDDING_MODEL`, `AWS_REGION` and `AWS_PROFILE`.

[cols="1,3",options="header"]
|===
|Tool |Parameters and behavior

|`search_context` |`query`, `user_id`, `top_k=10`, `min_score=0.5`, `include_relationships=True`. Searches messages, entities and preferences.
|`get_entity_graph` |`entity_name`, `user_id`, `depth=2`, `relationship_types=None`. Returns the relationships around one entity.
|`add_memory` |`content`, `user_id`, `session_id=None`, `extract_entities=True`. Stores a user message, in session `strands-<user_id>` when no session is given.
|`get_user_preferences` |`user_id`, `category=None`. Searches stored preferences, optionally by category. The results are not filtered by `user_id`.
|===

The factory caches one client per URI, user and database; call `clear_client_cache()` when ending their lifecycle. `nams_context_graph_tools(...)` exposes hosted operations with a workspace key. `bedrock_llm_model()` and `bedrock_embedding_model()` return Bedrock model IDs, honoring `BEDROCK_MODEL_ID` and `BEDROCK_EMBEDDING_MODEL_ID`. `llm_provider_from_strands(model)` turns a Strands model ID into an `LLMProvider` when you want the same model for memory extraction.

Await writes, check the applicable extraction lifecycle, and apply workspace/database authorization before another agent retrieves results. A shared graph makes permitted records available through retrieval; it does not broadcast every fact immediately to every agent. `user_id` and session grouping do not provide universal entity isolation.

=== Limitations

* One `Agent` per session manager. Attaching a second `Agent` raises `SessionException`, because one manager tracks one agent's turns. Once that agent is freed, another can attach. A turn the freed agent left paused at an interrupt is dropped then, with a warning, since nothing can resume it. After a call whose end the manager missed, the manager keeps that agent until it closes, so another agent still cannot attach. Attaching `Neo4jSessionManager` to a Strands Graph, Swarm or `BidiAgent` raises `NotImplementedError` at the first dispatch; use one of Strands' repository-backed managers for those topologies.
* Text turns are restored; tool-use blocks and `agent.state` are not. Set `record_tool_calls=True` to keep an audit record of tool use.
* Restored history alternates roles and starts with a user message. Consecutive assistant messages are merged, and leading assistant messages are dropped. User messages that never got a reply are left out, with a warning. This covers an earlier prompt in a run of user messages and a final user message. Stored messages are not changed.
* Pass `settings=` or an unconnected `memory_client=`. A client already connected on another event loop cannot be driven from the manager's background loop.
* Guardrail redaction rewrites the latest message before it is stored. A redaction that lands while the message is being written is applied once the write finishes. After the message is stored, Bolt deletes it and re-adds the redacted message at the end of the history. NAMS cannot redact a stored message, so it logs a warning. A redaction that fails on a stored message is logged as an ERROR.
* The session manager writes a turn's messages when the agent call returns a result. A call that raises or is cancelled stores none of its messages, and an INFO log gives their number. `agent.cancel()` and a set `cancel_signal` count as a cancel. The `stop` tool ends a call with an answer, so its turn is written. The `limit_*` stop reasons write the turn too, because the caller got an answer. A turn paused by an interrupt is written when the call that resumes it returns. A resume that a BeforeInvocationEvent hook cancels keeps the turn paused for the next resume. A call that raises while Strands still holds an interrupt keeps its turn paused too, so the call that resumes it writes the whole turn. A process that stops mid-turn loses that turn.
* Run one agent call at a time per session manager. Calls that overlap on one agent fold into the first call's turn. A `structured_output_async` call during `invoke_async` is one example. A second call in `UNSAFE_REENTRANT` mode is another. The overlapping call logs a warning, and its messages join the open turn. The first call's result decides whether that turn is written, so a failed overlapping call discards nothing. This has four limits. If the first call fails, the overlapping call's messages are discarded with its turn. If the first call ends while an overlapping call still runs, its turn is written with the overlapping call's prompt. If that call then fails, the rest of its messages are discarded, so its prompt is stored without a reply. This can happen only in `UNSAFE_REENTRANT` mode. If `structured_output_async` starts first and `invoke_async` overlaps it, the structured call decides the turn. It reports no result, so the whole turn is discarded. If a `BeforeInvocationEvent` hook raises in an overlapping call, the manager keeps counting that call. A later `structured_output_async` call then leaves its turn open. The next call ends that turn and resets the count. In `UNSAFE_REENTRANT` mode, an overlapping `structured_output_async` call whose `AfterInvocationEvent` never reaches the manager can leave the manager counting that call too. A call whose `AfterInvocationEvent` never reaches the manager never ends its turn. A hook that raises before the manager's hook causes this. So does a hook that raises after the manager's `BeforeInvocationEvent` hook. The next call logs a warning and discards that turn, as for any call that raised. A turn that stopped at an interrupt is kept instead, so the call that resumes it writes the whole turn. A resume that stops at a second interrupt and whose end is missed loses the assistant message it added. Messages appended outside a call while that turn stayed open are discarded with it. A direct `agent.tool` call is one example. In `UNSAFE_REENTRANT` mode, a task that awaits its calls one after another never finds that turn left over. No later turn is written, and close logs those messages as unwritten. Closing the manager while an agent call is still running logs an ERROR, and that call's turn is not written.
* Strands' experimental durable checkpoints are not supported. A call that stops with stop reason `"checkpoint"` is written as a finished turn, and the call that resumes it writes a new turn.
* Hooks for `AfterInvocationEvent` registered after the session manager run before the turn is stored; read persisted state on the next turn.
